# Маркетинг-стратег
 
Скилл — папка с инструкциями и скриптами, по которым ИИ-агент готовит маркетинговую стратегию вместе с маркетологом. «Маркетинг-стратег» отвечает за то, что происходит до первой кампании в кабинете: разбирает продукт и сайт, изучает отрасль и конкурентов, собирает гипотезы, портреты покупателей и УТП, ранжирует площадки, раскладывает бюджет по фазам и задаёт KPI.

Для старта хватает названия продукта и ссылки на сайт. На выходе — отчёт-стратегия, медиаплан и резюме на страницу, а рядом с ними файлы всех этапов: по ним видно, откуда взялось каждое решение.

## Маршрут

Подготовительный шаг заводит рабочую папку `marketing-campaigns/<slug>/` и файл состояния `_state.json` — в `SKILL.md` он идёт под номером 0. Дальше — 12 этапов; каждый заканчивается файлом в этой папке и короткой сводкой в чат.

| Этап | Что делает агент | Что остаётся в папке |
|---|---|---|
| 1. Материалы клиента | разбирает бриф, презентации, переписку и отчёты прошлых кампаний по схеме «факт → источник»; прошлые цифры по каналам — в историю каналов | `00_client_materials.md` |
| 2. Бриф | читает сайт, недостающее спрашивает одним списком: посадочная страница, регион, бизнес-цель и конверсия на сайте, юнит-экономика, бюджет, **горизонт планирования** (по умолчанию 6 месяцев), сезонность, исключения, **история рекламы**, тематика. С Метрикой — сколько лидов и какая конверсия у сайта сейчас и история каналов по источникам | `01_brief.md`, `channel_history.md` |
| 3. Стратегическая рамка | запрашивает в Вордстате частотность запросов ниши — один раз, цифры дальше берут этапы 4 и 9; фиксирует тип спроса, воронку, цели на контрольных точках горизонта из брифа и явные исключения: площадки, форматы и темы, которые на проекте не используются | `03_demand.md`, `02_strategy.md` |
| 4. Отрасль | ищет диапазоны CAC и LTV, рабочие каналы ниши и типичные ошибки в ней — со ссылками на использованные источники | `industry_research.md`, `industry_research.json` |
| 5. Конкуренты | отбирает 5–10 кандидатов, разбирает выбранные пять и строит матрицу «конкурент × канал» | `04_competitors.md`, `05_competitor_analysis.md`, `competitor_matrix.json` |
| 6. Гипотезы | формулирует 5–8 гипотез «кому → что обещаем → где проверяем»; на тест уходят 2–4 | `hypotheses.md` |
| 7. Портреты покупателей | описывает 3–5 сегментов: боли, возражения, триггеры покупки и цифровой след | `07_personas.md` |
| 8. УТП | делит заявления сайта на УТП, довески и шум, проверяет кандидатов по пяти критериям Котлера | `usp_audit.md`, `usp_candidates.md`, `usp_final.json` |
| 9. Выбор площадок | оценивает каналы по шести критериям, сверяет с историей клиента (канал, который уже не дал лидов или вышел дорогим, попадает в финал только решением маркетолога) и выводит три с приоритетами 1/2/3; без истории — пометка «без истории» | `channel_selection.md`, `channel_selection.json` |
| 10. Бюджет | раскладывает деньги на горизонт из брифа по трём фазам: тест, оптимизация, масштаб | `budget_allocation.md`, `budget_allocation.json` |
| 11. KPI | задаёт целевые значения по фазам и триггеры «сократить / усилить / отключить» | `kpi_framework.md`, `kpi_framework.json` |
| 12. Документы и передача | собирает итоговые документы и план передачи в скилл площадки | `12_handoff_plan.md` и три документа |

Каждый этап опирается на свой справочник из `references/` — все справочники лежат в самом пакете. На семи этапах `SKILL.md` требует прочитать справочник целиком, а не просмотреть.

Этапы 4 и 5 собирают много сырья: выдачу поиска и полные тексты сайтов конкурентов. В чат оно не выливается — уходит сразу в файлы, наверх поднимаются только сводка и матрица.

Режима два. **Пошаговый** останавливается после каждого этапа и ждёт подтверждения. **Быстрый** останавливается на шести решениях, которые меняют всё дальнейшее: бриф, гипотезы, УТП, площадки, бюджет и сборка документов. Там, где этап требует выбора, подтверждением считается сам выбор, а не слово «ок».

Состояние живёт в `_state.json`. Если сессия прервалась, скажите агенту, что продолжаете стратегию по этому продукту: он прочитает `current_step` и пойдёт дальше с того же места.

## Установка

Пакет устроен как папка скилла: `SKILL.md` в корне, рядом `references/` и `scripts/`. Агентная среда — программа, в которой работает агент, — берёт скиллы из своего каталога.

Проще всего — из каталога плагинов [claude-plugins](https://github.com/ai-hub-open/claude-plugins): там же выбор способа установки ([какой способ выбрать](https://github.com/ai-hub-open/claude-plugins#какой-способ-установки-выбрать)) и включение автообновления.

### Claude Desktop — через интерфейс

Нужен Git ([как поставить](https://github.com/ai-hub-open/claude-plugins#шаг-1-установите-git)); после его установки перезапустите Claude Desktop. **Settings → Plugins** → **+ → Add marketplace → Add from repository** → `https://github.com/ai-hub-open/claude-plugins` → в каталоге **ai-hub-open** нажмите **Add** у `marketing-strategist`. Автообновление — переключатель **Auto-update** у каталога там же, в **Settings → Plugins** ([по шагам](https://github.com/ai-hub-open/claude-plugins#установка-в-claude-desktop)).

### Claude Code — плагином, с обновлениями

В сессии Claude Code:

```
/plugin marketplace add ai-hub-open/claude-plugins
/plugin install marketing-strategist@ai-hub-open
```

Скилл вызывается как `/marketing-strategist:marketing-strategist` или просьбой своими словами («нужна маркетинговая стратегия»).

Затем включите автообновление: `/plugin` → **Marketplaces** → `ai-hub-open` → **Enable auto-update**. С ним новые версии приходят сами при старте сессии. Без него — командой `/plugin marketplace update ai-hub-open`.

Библиотеки для документов этапа 12 плагин сам не ставит — см. [Требования](#требования). Если раньше скилл лежал папкой в `~/.claude/skills/marketing-strategist`, удалите её, иначе скилл будет загружаться дважды.

### Claude Code — папкой

```bash
git clone https://github.com/ai-hub-open/marketing-strategist.git
mkdir -p ~/.claude/skills/marketing-strategist
cp -r marketing-strategist/SKILL.md marketing-strategist/VERSION marketing-strategist/references marketing-strategist/scripts \
      ~/.claude/skills/marketing-strategist/
```

Копируются только эти четыре пути (по `VERSION` скилл узнаёт, что вышла новая версия): остальное в репозитории — сборка, проверки и этот файл — скиллу не нужно.

### Архивом (claude.ai, любой тариф)

Скачайте `marketing-strategist.zip` из блока **Assets** [последнего релиза](https://github.com/ai-hub-open/marketing-strategist/releases/latest) (не «Source code»). Включите **Settings → Capabilities → Code execution and file creation** и загрузите архив в **Customize → Skills → + → Create skill → Upload a skill**.

Загрузчик принимает zip, внутри которого одна папка верхнего уровня и ровно один `SKILL.md`. Архив можно собрать и из репозитория:

```bash
pip install pyyaml
python tools/build_skill_zip.py          # → dist/marketing-strategist.zip
```

Перед упаковкой скрипт проверяет пакет: `SKILL.md` лежит в корне и он один, во фронтматтере — YAML-шапке файла — только `name` и `description`, описание не длиннее 200 символов, каждый путь `references/…` и `scripts/…`, упомянутый в `SKILL.md`, существует. Что-то не сошлось — архив не собирается, и в stderr написано, что именно. Запустить только проверку, без сборки: `python tools/build_skill_zip.py --check`.

Собранный архив загружается так же — через **Customize → Skills**.

Кнопка **Code → Download ZIP** для этого не годится: она отдаёт папку `marketing-strategist-main/` с файлами репозитория, которых загрузчик не ждёт.

## Запуск

Держите под рукой название продукта, ссылку на сайт и материалы клиента, если они есть. В строку чата:

```
/marketing-strategist Подготовь маркетинговую стратегию для <продукт>, сайт <адрес>.
```

Агент предложит имя рабочей папки по названию продукта, спросит режим и сразу перейдёт к материалам и брифу; горизонт планирования (по умолчанию 6 месяцев) он уточнит вместе с брифом. На первом проекте берите пошаговый режим: видно каждое решение и место, где ваше слово весит больше всего. Если среда передаёт параметры запуска (папку и режим), агент сразу переходит к материалам и брифу.

Скилл запускается и без команды: во фронтматтере перечислены триггеры — «маркетинговая стратегия», «медиаплан», «какие каналы выбрать». Если в запросе уже назван канал, автоматический запуск не срабатывает: сравнивать нечего, дальше работает скилл площадки.

## Что на выходе

Три документа, с которыми идут защищать проект:

- `marketing_strategy.docx` — продукт и аудитория, конкурентный контекст, УТП, площадки с приоритетами и историей клиента по каждой, бюджет по фазам, KPI, план передачи;
- `media_plan.xlsx` — фаза × канал × неделя с бюджетами и целевыми показателями;
- `strategy_summary.pdf` — резюме на страницу для того, кто принимает решение и не будет читать отчёт целиком.

Если Яндекс Директ в топ-3 — ещё `12_brief_for_yandex_direct.md`: бриф в формате скилла `yandex-direct-manager`, чтобы тот не задавал те же вопросы второй раз.

Рядом остаётся папка кампании целиком: бриф, отраслевые данные, матрица конкурентов, гипотезы, портреты, разбор УТП, оценка каналов, бюджет, KPI. Любое число из отчёта прослеживается до файла, в котором оно появилось.

Документы собирают три скрипта; каждый принимает путь к папке кампании:

```bash
python scripts/generate_strategy_doc.py    --workspace marketing-campaigns/<slug>
python scripts/generate_media_plan_xlsx.py --workspace marketing-campaigns/<slug>
python scripts/generate_pdf_summary.py     --workspace marketing-campaigns/<slug>
```

Нужной библиотеки в среде нет — скрипт не прерывается с ошибкой, а сохраняет то же содержимое текстом: `marketing_strategy.md`, `media_plan/summary.csv`, `strategy_summary.md`.

Полноту материалов скрипты за агента не проверяют. Если не хватает `01_brief.md`, `02_strategy.md`, `usp_final.json`, `channel_selection.json`, `budget_allocation.json` или `kpi_framework.json`, в stderr уходит предупреждение, а документ собирается с пробелами на месте пропусков. Маршрут в `SKILL.md` сверяет тот же список раньше и не даёт запустить сборку.

## Требования

- **Агентная среда**, которая читает скиллы из своего каталога.
- **Доступ агента в интернет.** Без него не проходят этапы 2, 4 и 5: сайт, отрасль и конкуренты читаются из сети.
- **Python 3** — только для сборки документов на этапе 12. В проверках репозитория скрипты запускаются на версии 3.12.
- **Необязательные библиотеки:** `pip install python-docx openpyxl reportlab`. Без них выход тот же по содержанию, но текстом.
- **Коннекторы данных — необязательные.** Без них стратег работает как раньше, но тип спроса и цели KPI
  оценивает качественно и прямо пишет «нет данных» (подробнее — [Коннекторы](#коннекторы)):
  - **Вордстат** — частотность спроса по нише в регионе, один запрос частотностей на этапе 3;
  - **Метрика** — только чтение: сколько лидов и какая конверсия у сайта сейчас, история каналов по
    источникам трафика, точка отсчёта для KPI.
- **Системный шрифт с кириллицей** для PDF: DejaVu на Linux, Arial на macOS и Windows. Ни одного из известных путей нет — скрипт предупреждает в stderr и называет, что поставить; PDF при этом соберётся, но русский текст в нём будет нечитаемым.

## Коннекторы

Коннекторы работают по MCP — это подключение агента к рекламной системе, здесь к Вордстату и Метрике. Оба MCP-сервера размещены на стороне click.ru — разворачивать ничего не нужно. Адрес содержит токен и равносилен паролю: не пересылайте его и не
вставляйте в общие чаты.

| Коннектор | Адрес | Зачем стратегу |
|---|---|---|
| Вордстат | `https://wordstat-mcp.aihub.click.ru/c/<API-токен click.ru>` | показы в месяц по запросам ниши — тип спроса (этап 3), спрос в нише (этап 4), вес поисковых каналов (этап 9) |
| Метрика | `https://metrika-mcp.aihub.click.ru/c/<API-токен click.ru>` (один аккаунт — `…/c/<токен>/<аккаунт>`, без click.ru — `…/y/<OAuth-токен Яндекса>`) | лиды и конверсия сайта сейчас, история каналов, точка отсчёта KPI (этапы 2 и 11); только чтение |

API-токен click.ru — профиль https://click.ru/userinfo.html → «API Token». Для Метрики в click.ru должна
быть подключена интеграция Метрики.

- **Claude Desktop и claude.ai:** Settings → Connectors → Add custom connector, в поле URL — адрес.
- **Claude Code:**

  ```bash
  claude mcp add --scope user --transport http yandex-wordstat "<адрес Вордстата>"
  claude mcp add --scope user --transport http yandex-metrika "<адрес Метрики>"
  ```

Имя коннектора может быть любым: стратег находит его по инструментам (`…wordstat_shows_batch`,
`…yandex_metrika_counters_get`), а не по имени. Коннекторов Метрики несколько — спросит, какой клиент.

## Границы

- Доступы к рекламным кабинетам не нужны и не запрашиваются: агент не обращается к API площадок, не создаёт кампании и не тратит бюджет. Работа заканчивается документами.
- Объявления, креативы и саму кампанию собирают скиллы площадок: [`yandex-direct-manager`](https://github.com/ai-hub-open/yandex-direct-manager) для Яндекс Директа, [`vk-ads-manager`](https://github.com/ai-hub-open/vk-ads-manager) для VK Рекламы. Готовый набор файлов на передачу собран для этих двух каналов; для остальных `12_handoff_plan.md` перечисляет, что взять, дальше — вручную.
- Передача происходит только после того, как канал назвали вы. Сам себя следующий скилл не вызывает.
- Стратега скилл не заменяет: гипотезы, УТП, площадки и бюджет подтверждает маркетолог.
- Чего нет в источниках, агент помечает как непроверенное и не достраивает по догадке. Помеченные места маркетолог проверяет вручную.
- Маршрут, справочники и собираемые документы — на русском.
