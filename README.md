# Маркетинг-стратег

Скилл — папка с инструкциями и скриптами, по которым ИИ-агент выполняет работу маркетолога. «Маркетинг-стратег» отвечает за то, что происходит до первой кампании в кабинете: разбирает продукт и сайт, изучает отрасль и конкурентов, собирает гипотезы, портреты покупателей и УТП, ранжирует площадки, раскладывает бюджет по фазам и задаёт KPI.

Для старта хватает названия продукта и ссылки на сайт. На выходе — отчёт-стратегия, медиаплан и резюме на страницу, а рядом с ними файлы всех этапов: по ним видно, откуда взялось каждое решение.

## Маршрут

Подготовительный шаг заводит рабочую папку `marketing-campaigns/<slug>/` и файл состояния `_state.json` — в `SKILL.md` он идёт под номером 0. Дальше — 12 этапов; каждый заканчивается файлом в этой папке и короткой сводкой в чат.

| Этап | Что делает агент | Что остаётся в папке |
|---|---|---|
| 1. Материалы клиента | разбирает бриф, презентации, переписку и отчёты прошлых кампаний по схеме «факт → источник» | `00_client_materials.md` |
| 2. Бриф | читает сайт, недостающее спрашивает одним списком: регион, бизнес-цель, юнит-экономика, бюджет, сезонность, исключения | `01_brief.md` |
| 3. Стратегическая рамка | фиксирует тип спроса, воронку, цели на 1, 3 и 6 месяцев и явные исключения: площадки, форматы и темы, которые на проекте не используются | `02_strategy.md` |
| 4. Отрасль | ищет диапазоны CAC и LTV, рабочие каналы ниши и её анти-паттерны — со ссылками на использованные источники | `industry_research.md`, `industry_research.json` |
| 5. Конкуренты | отбирает 5–10 кандидатов, разбирает выбранные пять и строит матрицу «конкурент × канал» | `04_competitors.md`, `05_competitor_analysis.md`, `competitor_matrix.json` |
| 6. Гипотезы | формулирует 5–8 гипотез «кому → что обещаем → где проверяем»; на тест уходят 2–4 | `hypotheses.md` |
| 7. Портреты покупателей | описывает 3–5 сегментов: боли, возражения, триггеры покупки и цифровой след | `07_personas.md` |
| 8. УТП | делит заявления сайта на УТП, довески и шум, проверяет кандидатов по пяти критериям Котлера | `usp_audit.md`, `usp_candidates.md`, `usp_final.json` |
| 9. Выбор площадок | оценивает каналы по шести критериям и выводит в финал три с приоритетами 1/2/3 | `channel_selection.md`, `channel_selection.json` |
| 10. Бюджет | раскладывает деньги по трём фазам: тест, оптимизация, масштаб | `budget_allocation.md`, `budget_allocation.json` |
| 11. KPI | задаёт целевые значения по фазам и триггеры «сократить / усилить / отключить» | `kpi_framework.md`, `kpi_framework.json` |
| 12. Документы и передача | собирает итоговые документы и план передачи в скилл площадки | `12_handoff_plan.md` и три документа |

Каждый этап опирается на свой справочник из `references/` — одиннадцать методичек лежат в самом пакете. На семи этапах `SKILL.md` требует прочитать справочник целиком, а не просмотреть.

Этапы 4 и 5 собирают много сырья: выдачу поиска и полные тексты сайтов конкурентов. В чат оно не выливается — уходит сразу в файлы, наверх поднимаются только сводка и матрица.

Режима два. **Пошаговый** останавливается после каждого этапа и ждёт подтверждения. **Быстрый** останавливается на шести решениях, которые меняют всё дальнейшее: бриф, гипотезы, УТП, площадки, бюджет и сборка документов. Там, где этап требует выбора, подтверждением считается сам выбор, а не слово «ок».

Состояние живёт в `_state.json`. Если сессия прервалась, скажите агенту, что продолжаете стратегию по этому продукту: он прочитает `current_step` и пойдёт дальше с того же места.

## Установка

Пакет устроен как папка скилла: `SKILL.md` в корне, рядом `references/` и `scripts/`. Агентная среда — программа, в которой работает агент, — берёт скиллы из своего каталога.

### Claude Code

```bash
git clone https://github.com/ai-hub-open/marketing-strategist.git
mkdir -p ~/.claude/skills/marketing-strategist
cp -r marketing-strategist/SKILL.md marketing-strategist/references marketing-strategist/scripts \
      ~/.claude/skills/marketing-strategist/
```

Копируются только три пути: остальное в репозитории — сборка, проверки и этот файл — скиллу не нужно.

### Claude Desktop и claude.ai

Загрузчик принимает zip, внутри которого одна папка верхнего уровня и ровно один `SKILL.md`. Соберите архив из репозитория:

```bash
pip install pyyaml
python tools/build_skill_zip.py          # → dist/marketing-strategist.zip
```

Перед упаковкой скрипт проверяет пакет: `SKILL.md` лежит в корне и он один, во фронтматтере — YAML-шапке файла — только `name` и `description`, описание не длиннее 200 символов, каждый путь `references/…` и `scripts/…`, упомянутый в `SKILL.md`, существует. Что-то не сошлось — архив не собирается, и в stderr написано, что именно. Прогнать одну проверку без сборки: `python tools/build_skill_zip.py --check`.

Готовый архив загружается через **Settings → Capabilities → Skills**.

Кнопка **Code → Download ZIP** для этого не годится: она отдаёт папку `marketing-strategist-main/` с файлами репозитория, которых загрузчик не ждёт.

## Запуск

Держите под рукой название продукта, ссылку на сайт и материалы клиента, если они есть. В строку чата:

```
/marketing-strategist Подготовь маркетинговую стратегию для <продукт>, сайт <адрес>.
```

Агент спросит короткое имя продукта — оно станет именем рабочей папки, — предложит режим и пойдёт по этапам. На первом проекте берите пошаговый: видно каждое решение и место, где ваше слово весит больше всего.

Скилл поднимается и без команды: во фронтматтере перечислены триггеры — «маркетинговая стратегия», «медиаплан», «какие каналы выбрать». Если в запросе уже назван канал, автоматический подъём не срабатывает: сравнивать нечего, дальше работает скилл площадки.

## Что на выходе

Три документа, с которыми идут защищать проект:

- `marketing_strategy.docx` — продукт и аудитория, конкурентный контекст, УТП, площадки с приоритетами, бюджет по фазам, KPI, план передачи;
- `media_plan.xlsx` — фаза × канал × неделя с бюджетами и целевыми показателями;
- `strategy_summary.pdf` — резюме на страницу для того, кто принимает решение и не будет читать отчёт целиком.

Рядом остаётся папка кампании целиком: бриф, отраслевые данные, матрица конкурентов, гипотезы, портреты, разбор УТП, оценка каналов, бюджет, KPI. Любое число из отчёта прослеживается до файла, в котором оно появилось.

Документы собирают три скрипта; каждый принимает путь к папке кампании:

```bash
python scripts/generate_strategy_doc.py    --workspace marketing-campaigns/<slug>
python scripts/generate_media_plan_xlsx.py --workspace marketing-campaigns/<slug>
python scripts/generate_pdf_summary.py     --workspace marketing-campaigns/<slug>
```

Нужной библиотеки в среде нет — скрипт не падает, а сохраняет то же содержимое текстом: `marketing_strategy.md`, `media_plan/summary.csv`, `strategy_summary.md`.

Полноту материалов скрипты за агента не проверяют. Если не хватает `01_brief.md`, `02_strategy.md`, `usp_final.json`, `channel_selection.json`, `budget_allocation.json` или `kpi_framework.json`, в stderr уходит предупреждение, а документ собирается с пробелами на месте пропусков. Маршрут в `SKILL.md` сверяет тот же список раньше и не даёт запустить сборку.

## Требования

- **Агентная среда**, которая читает скиллы из своего каталога.
- **Доступ агента в интернет.** Без него не проходят этапы 2, 4 и 5: сайт, отрасль и конкуренты читаются из сети.
- **Python 3** — только для сборки документов на этапе 12. В проверках репозитория скрипты прогоняются на версии 3.12.
- **Необязательные библиотеки:** `pip install python-docx openpyxl reportlab`. Без них выход тот же по содержанию, но текстом.
- **Системный шрифт с кириллицей** для PDF: DejaVu на Linux, Arial на macOS и Windows. Ни одного из известных путей нет — скрипт предупреждает в stderr и называет, что поставить; PDF при этом соберётся, но русский текст в нём будет нечитаемым.

## Границы

- Доступы к рекламным кабинетам не нужны и не запрашиваются: агент не обращается к API площадок, не создаёт кампании и не тратит бюджет. Работа заканчивается документами.
- Объявления, креативы и саму кампанию собирают скиллы площадок: [`yandex-direct-manager`](https://github.com/ai-hub-open/yandex-direct-manager) для Яндекс Директа, [`vk-ads-manager`](https://github.com/ai-hub-open/vk-ads-manager) для VK Рекламы. Готовый набор файлов на передачу собран для этих двух каналов; для остальных `12_handoff_plan.md` перечисляет, что взять, дальше — руками.
- Передача происходит только после того, как канал назвали вы. Сам себя следующий скилл не вызывает.
- Стратега скилл не заменяет: гипотезы, УТП, площадки и бюджет подтверждает маркетолог.
- Чего нет в источниках, агент помечает как непроверенное и не достраивает по догадке. Помеченные места разбираются руками.
- Маршрут, справочники и собираемые документы — на русском.
