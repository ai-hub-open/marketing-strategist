# Журнал изменений

Версии — [semver](https://semver.org/lang/ru/). Описание для пользователей — `docs/releases/`.

## 1.1.0 — 2026-10-09

**Артефакты на диске и вывод наверху.** Шаг считается сделанным, только когда его файл записан
в `marketing-campaigns/<slug>/`, и каждый файл начинается с вывода. Описание для пользователей —
[`docs/releases/v1.1.0.md`](docs/releases/v1.1.0.md).

- **Правило артефакта** (`SKILL.md`, оба режима): сначала запись файла, потом сводка в чат, потом
  «ОК». Блок «✋ Подтверди» открывается строкой `📄 Записано: …`. Запись не удалась — стратег
  говорит об этом и останавливается, а не отчитывается «готово».
- **Правило структуры артефакта:** `# Заголовок` → `## Вывод` (3-7 строк) → сводная таблица →
  остальное. «Не нашли» — тоже вывод и идёт наверх. У каждой таблицы со значками ✅/⚠️/❌ —
  легенда под ней. Шаблоны артефактов в `references/` приведены к этому порядку.
- **`media_plan.xlsx`, лист «По неделям»:** фаза без `duration_weeks` давала шапку короче строк —
  колонка «Всего» съезжала, формула суммы теряла последнюю неделю. Теперь длительность фазы
  считается одинаково в шапке и строках (не меньше 1 недели).
- **`strategy_summary.pdf`:** предупреждение о недостающих артефактах, как у двух других
  генераторов, вместо молча собранного резюме с прочерками.

## 1.0.2 — 2026-10-08

- **Передача в Директ находит скилл под любым именем.** `yandex-direct-manager` 0.18.0 ставится
  плагином Claude Code и вызывается как `/yandex-direct-manager:yandex-direct-manager`. Шаг 12В
  принимает и это имя, и `/yandex-direct-manager` (установка папкой), и префикс набора в Claude
  Desktop / claude.ai. Описание для пользователей —
  [`docs/releases/v1.0.2.md`](docs/releases/v1.0.2.md).

## 1.0.1 — 2026-10-06

- **`strategy_summary.pdf` больше не падает на «<» и «&» в данных.** Обоснование канала, УТП,
  вывод истории («порог: <30 кликов») и другие строки из артефактов передавались в ReportLab
  как разметка: непарный тег ронял сборку PDF, `<b>` из данных применялся как форматирование.
  Теперь весь текст из данных экранируется. Описание для пользователей —
  [`docs/releases/v1.0.1.md`](docs/releases/v1.0.1.md).

## 1.0.0 — 2026-10-06

**История рекламы клиента и передача в Яндекс Директ.** Стратег больше не выбирает каналы «из
общих знаний»: сначала узнаёт, что прошлая реклама клиента реально дала, и не пускает в топ-3
то, что уже провалилось, без явного решения маркетолога. Описание для пользователей —
[`docs/releases/v1.0.0.md`](docs/releases/v1.0.0.md).

- **Горизонт планирования — одно число на весь прогон** (по умолчанию 6 месяцев): задаётся в
  брифе, подтверждается на Шаге 0, стратегия, бюджет, медиаплан и скрипты только читают его.
- **История каналов на входе.** Новое поле 12 брифа и `references/channel-history.md`: файл
  `channel_history.md` от `yandex-direct-audit` или слова клиента, период всегда спрашивается,
  «что считать лидом» — с вариантами. Контракт файла общий с `yandex-direct-audit` и
  `yandex-direct-manager`. Рекламы не было — каналы помечаются «без истории».
- **Шаг 9: история — фильтр поверх баллов.** `works` даёт +1 к доказательной базе; канал с
  `no_leads` или `expensive` попадает в топ-3 только решением маркетолога с цифрами и ответом
  «что меняем». В матрице — колонка «История», в `channel_selection.json` — поле `history`,
  в `marketing_strategy.docx` и `strategy_summary.pdf` — строка «История у клиента».
- **VK и похожие аудитории убраны из дефолтных топ-3** в сценариях бюджета: сценарии —
  иллюстрация раскладки, каналы берутся только из Шага 9; LAL — только при базе для похожих.
- **Бриф:** посадочная страница, конверсия на сайте (и есть ли счётчик Метрики), история
  рекламы, тематика с документами.
- **Передача в Яндекс Директ:** `12_brief_for_yandex_direct.md` — бриф в формате
  `yandex-direct-manager` (13 пунктов, стоп-поля не придумываются, а помечаются «❗ уточнить»)
  + `channel_history.md`. Устаревшее описание шагов менеджера (19 шагов) заменено актуальным.
