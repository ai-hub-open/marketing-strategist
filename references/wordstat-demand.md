# Спрос по Вордстату: один пробив на Шаге 3

Используется на Шаге 3, цифры переиспользуют Шаги 4 и 9. Задача — заменить догадку «спрос, кажется,
есть» числом показов в месяц по запросам ниши в регионе клиента. Пробив делается **один раз за
прогон**; Шаги 4 и 9 читают `03_demand.md` и не пробивают заново.

## Подключение

Коннектор — хостовый MCP Вордстата click.ru: `https://wordstat-mcp.aihub.click.ru/c/<токен click.ru>`.
Токен — профиль click.ru → «API Token». Адрес равносилен паролю: в чат и в артефакты не пиши.

- **Ищи инструмент, а не имя сервера.** Сервер могут назвать как угодно (`yandex-wordstat`,
  `Wordstat`, `wordstat-mcp`). Признак нужного — инструмент, чьё имя оканчивается на
  `wordstat_shows_batch`. В средах с отложенной загрузкой инструментов сначала поищи его
  механизмом поиска среды (в Claude Code — `ToolSearch`), потом решай, что его нет.
- Сервер отвечает только «сколько показов у фразы». Похожих запросов, динамики и сезонности в нём
  нет — сезонность остаётся вопросом брифа (поле 9) и отраслевой аналитики.

## Пробив

1. **Собери 10-30 маркерных запросов** из брифа: продукт и его синонимы × намерение × география.
   - Транзакционные (готов купить): `<продукт> купить`, `<продукт> цена`, `<услуга> заказать`,
     `<услуга> <город>`, `<продукт> стоимость`.
   - Информационные (изучает): `как выбрать <продукт>`, `<продукт> отзывы`, `<проблема> что делать`.
   - Проблемные (ещё не знает решения): боль клиента словами клиента — из брифа и материалов.
   - Бренды 1-2 известных конкурентов — если названы в брифе.
   Не больше 30: это проверка спроса, а не сбор семантики.
2. **Один вызов** `…wordstat_shows_batch({ keywords: [...], region_id: <регион брифа> })`.
   Регион: 225 — Россия, 213 — Москва, 1 — Москва и область, 2 — Санкт-Петербург. Несколько
   регионов в брифе — вызов на каждый, итог сложи и запиши, по каким регионам считал.
3. **Читай ответ построчно:** `stat` — показов в месяц (`0` — валидное значение), `error: 110` —
   ещё считается (добери повторным вызовом только эти фразы), `cache_date` — дата замера.
   Кэш старше 12 месяцев — пометь фразу «устаревшая частотность», выводы по ней ориентировочные.
4. **Сбой шлюза** (`502`, таймаут): один повтор через 5 секунд, потом — как «нет подключения» ниже.

## Как читать цифры

| Сумма показов в месяц по **транзакционным** маркерам в регионе | Что это значит для Шага 3 |
|---|---|
| ≥ 1 000 | спрос есть: **срочный** (покупают сейчас) или **отложенный** (выбирают), решают доли информационных запросов |
| 100-1 000 | спрос узкий: поисковые каналы — точечно, основной объём придётся создавать |
| < 100 | готового спроса почти нет: **создаём спрос** — поиск не может быть основным каналом |

Пороги — ориентир для массового B2C. Для B2B, дорогого чека и узких ниш порог ниже: 200 показов
«оборудование для пекарни купить» могут быть всем рынком. Решение на гейте за маркетологом —
покажи цифры, а не только вывод.

## Артефакт: `03_demand.md`

```markdown
# Спрос по Вордстату: <slug>

## Вывод

[3-5 строк: суммы показов по группам, что это значит для типа спроса, на сколько процентов спрос
по поиску закрывает план лидов из брифа. Нет подключения — «частотность: нет данных» первой строкой.]

## Таблица

| Запрос | Группа | Показов в месяц | Регион | Дата замера |
|---|---|---:|---|---|

**Группы:** транзакционный — готов купить; информационный — изучает; проблемный — ещё не знает
решения; бренд — ищет конкурента по имени. «⚠️ устаревшая» — замер старше 12 месяцев.
```

И `demand` в `_state.json`: `wordstat` (пробили) или `none` (нет подключения).

## Кто читает цифры дальше

- **Шаг 4** — блок «типы спроса в нише»: сначала цифры из `03_demand.md`, потом поиск по нише.
- **Шаг 9** — критерий «Fit с типом спроса» и «Бюджет-эффективность» для поисковых каналов
  (Яндекс Директ — Поиск): мало транзакционных показов — поиск не может дать план лидов, даже если
  всё остальное сходится. Покажи это числом рядом с баллом канала.

## Нет подключения

Инструмента `*wordstat_shows_batch` нет ни под одним именем сервера (проверь, а не полагайся на
имя) или шлюз дважды не ответил — **шаг не останавливается**:

- `03_demand.md` всё равно пиши: первая строка вывода — «Частотность: нет данных — Вордстат не
  подключён». Тип спроса оцени качественно, как раньше: бриф (поле 9), материалы клиента, поиск.
- `_state.json: demand = none`. На гейте Шага 3 скажи одной строкой, что цифр спроса нет и как их
  получить: подключить коннектор Вордстата (адрес выше) или прислать частотности из интерфейса
  Вордстата.
- Цифры **не выдумывай** и не подставляй «примерно». «Нет данных» — тоже вывод.
