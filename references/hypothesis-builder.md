# Hypothesis Builder — гипотезы запуска (cross-channel)

Используется на Шаге 6. Гипотеза = стратегическое предположение о том, **какому сегменту ЦА что обещать и через какой канал**. Это не «креатив», а каркас для будущих кампаний на всех площадках.

## Главный принцип

**Гипотеза — это компактный конструкт «КТО → ЧТО → КАК (где проверяем)».** Без явного указания канала на этапе гипотезы мы потом будем тыкать пальцем в небо. Каждая гипотеза должна иметь **предварительный мэппинг канала**.

## Структура одной гипотезы

```markdown
### Гипотеза N: <короткое название, 3-5 слов>

**Сужающее слово / триггер сегмента:** одно ключевое слово, которое отделяет этот сегмент. Без него гипотеза «вообще про всех» — это не гипотеза.

**ЦА-сегмент:** одна-две фразы. Кто это конкретно.

**Главное обещание (УТП-черновик):** Что мы им говорим. Финализируется на Шаге 8.

**Углы коммуникации:** 2-3 разных подхода, как доносить (рациональный / эмоциональный / социальное доказательство).

**Канал-приоритет для проверки (предварительный):**
- Канал 1: <название> — почему именно тут
- Канал 2 (резерв): <название> — почему

(финальный выбор канала на Шаге 9, тут только предварительная привязка)

**Реализуемость на сайте:** ✅ / ⚠️ / ❌
- ✅ — на сайте есть нужная страница / блок / триал
- ⚠️ — частично, нужны правки
- ❌ — придётся делать новый лендинг

**Откуда взяли:** материалы клиента / industry research / анализ конкурентов / интуиция

**Гипотеза о результате:** что ожидаем (CPL, CR, объём)

**Риски:** что может пойти не так

**Зависимости:** что нужно подготовить для проверки
```

## Фаза 1 — Сырьё для гипотез

Источники (в порядке убывания силы):

1. **Материалы клиента** (`00_client_materials.md`) — клиент уже мог называть сегменты, на которые работает / хочет работать
2. **Анализ сайта** (Шаг 2, чтение веб-страниц) — какие сегменты уже видны на сайте по разделам/тарифам/кейсам
3. **Анализ конкурентов** (`05_competitor_analysis.md`) — на каких УТП и каналах работают они, какие сегменты упустили
4. **Industry research** (`industry_research.json`) — типовые сегменты в нише + где их находят
5. **Поиск на форумах и отзовиках** (например, `WebSearch`) — какие реальные люди пишут о своих болях

Источники 2 и 5 требуют способностей, которые есть не в каждой среде. Недоступны — работай на источниках 1, 3, 4, а гипотезы, у которых не осталось ни одного подтверждающего источника, помечай `source: гипотеза без подтверждения`: на Шаге 6 человек должен видеть, какие из них выбирает вслепую.

## Фаза 2 — Генерация 5-8 гипотез

Идём через **оси сегментации**:

### B2C-оси
- **Возраст** (студенты / 30+ / 45+)
- **Доход** (эконом / средний / премиум)
- **Триггер покупки** (срочно / планируют / в подарок / для семьи)
- **Уровень осведомлённости** (не знают категорию / знают / выбирают / лояльные)

### B2B-оси
- **Размер компании** (1-10 / 10-50 / 50+ сотрудников)
- **Роль ЛПР** (фаундер / маркетолог / финансист / HR)
- **Зрелость рынка** (используют конкурента / используют excel / ничего)
- **Триггер** (растут / падают / открываются / меняют поставщика)

Выбирай **разные оси** для каждой гипотезы. Если 3 гипотезы — это «премиум / эконом / средний» — это одна гипотеза с разной ценой, не три.

## Фаза 3 — Мэппинг гипотез на каналы

**Это новое относительно классического hypothesis builder.** Каждая гипотеза должна получить предварительный канал-приоритет ДО Шага 9, потому что:

- Гипотеза «срочно, ищут через поиск» → канал Я.Поиск
- Гипотеза «не знают категорию, нужен прогрев» → канал Дзен / контент
- Гипотеза «по интересам в сообществах» → канал VK Ads / LAL
- Гипотеза «короткое видео для молодёжи» → канал TikTok / Reels
- Гипотеза «эксперт-аудитория в нише» → канал Telegram / посевы

Это не финальный выбор (он на Шаге 9), а быстрый sanity-check: если гипотеза не привязывается ни к одному каналу — она нереализуемая в рекламе.

## Артефакт

### `hypotheses.md`

```markdown
# Гипотезы запуска: <slug>

**Источники:** 00_client_materials.md, 02_strategy.md, industry_research.json, 05_competitor_analysis.md
**Дата:** ...

## Все гипотезы (8)

[Карточки гипотез по шаблону выше]

## Сводная таблица

| # | Имя | Сегмент | Обещание | Канал-приоритет | Реализ. сайта | Гипотеза |
|---|-----|---------|----------|-----------------|:-------------:|----------|
| 1 | «Срочный перенос» | Владельцы салонов меняющие CRM | За 1 день, 0 потерь | Я.Поиск | ✅ | CPL 600₽ |
| 2 | «Стартап с 0» | Новые салоны открывающиеся | Бесплатный год | VK Ads + Дзен | ⚠️ нужна посадка | CPL 900₽ |
| 3 | «Сетевые 5+ точек» | Сетевые салоны | Аналитика по точкам | Я.Поиск + LinkedIn | ❌ нет лендинга | CPL 2000₽ |
| ... |

## Выбор для теста

[ждём от маркетолога: «беру 1, 2, 5»]
```

## Защита от типовых ошибок

**Ошибка 1:** «10 гипотез без приоритизации».
- Решение: 5-8 + явный выбор 2-4 для теста. Не больше.

**Ошибка 2:** «Гипотеза без сужающего слова».
- Решение: «Все владельцы салонов» — не гипотеза. «Владельцы салонов, **меняющие CRM**» — гипотеза.

**Ошибка 3:** «Гипотеза без канала».
- Решение: всегда предлагать 1-2 канала с обоснованием.

**Ошибка 4:** «Гипотеза неподтверждаемая на сайте».
- Решение: либо помечаем ❌ и добавляем «нужен новый лендинг», либо режем.

**Ошибка 5:** «Скопировал гипотезы конкурентов».
- Решение: гипотеза должна быть либо новая (gap), либо иметь чем выиграть аукцион (наша доказательная база сильнее).

## Гейт

Покажи таблицу. **«Беру гипотезы 1, 4, 7»** — это явный выбор. Не двигайся к Шагу 7 без явного списка.

`_state.json: selected_hypotheses: [1, 4, 7]`.
