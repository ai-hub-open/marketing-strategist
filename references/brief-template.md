# Brief Template — продуктовый бриф

Используется на Шаге 2. Задача — получить минимум 11 ключевых полей, чтобы дальнейшие шаги (стратегия, бюджетирование, медиаплан) опирались на факты, а не на догадки. Горизонт планирования — одно из них: без него этапы начнут считать каждый на свой срок.

## Главный принцип

**Минимальный вход — название + ссылка на сайт.** Всё остальное добываем через WebFetch на сайт + один блок из 11 вопросов маркетологу. Не задавай вопросы по одному, не вытягивай из клиента «всё что знаете» — задай блок, получи ответ, заполни пробелы.

## Что добываем сами (без вопросов клиенту)

**WebFetch на главную и ключевые страницы:**

| Поле | Как извлечь |
|------|-------------|
| Что за продукт | H1 главной + первый блок описания |
| Бенефиты | Список «преимуществ» / «возможностей» / «как это работает» |
| Цена / триал | Раздел «цены», «тарифы», «купить», «попробовать» |
| Доказательная база | Отзывы, кейсы, цифры, лого клиентов, рейтинги |
| CTA | Основная кнопка на первом экране |
| Тип сайта | Лендинг (1 экран + CTA) / интернет-магазин / SaaS / многостраничный |
| Контакты | Телефон / форма / чат |
| Гео | По языку, валюте, упомянутым городам |

Заблокирован WebFetch → проси у маркетолога 5 пунктов словами:
1. H1 главной
2. Основные бенефиты (3-5)
3. Главный CTA
4. Цена/триал
5. 1-2 цифры доказательной базы (количество клиентов, годы на рынке, и т.д.)

## 11 ключевых полей брифа

### Поле 1 — Что за продукт/услуга?
Название + одна фраза описания + ссылка на сайт.
Пример: «CRM-Flow — CRM для салонов красоты на 5-15 кресел. crm-flow.ru»

### Поле 2 — Тип сайта
- Лендинг (1-2 экрана + CTA)
- Многостраничный сайт
- Интернет-магазин (каталог + корзина)
- SaaS-кабинет (регистрация + триал)
- App-only (только мобильное приложение)

Тип сайта влияет на каналы (для App — Apple Search Ads / Google Play Ads).

### Поле 3 — Регион показа
- РФ (вся / город / список городов)
- СНГ
- Международно (какие страны)
- Локально + международно

Гео — ключевой фильтр для каналов: Meta доступна для не-РФ, в РФ через прокси-кабинеты.

### Поле 4 — Цель кампании
Что считаем результатом:
- **Лиды** (заявка / звонок / форма)
- **Продажи** (покупка / подписка)
- **Установки приложения**
- **Регистрации / триал**
- **Brand awareness** (охват, узнаваемость)
- **Контент-подписка** (рассылка, канал в TG)

Цель ≠ метрика. Цель — что мы делаем для бизнеса. Метрика — как меряем (см. Шаг 11).

### Поле 5 — Unit-экономика
- **CPA target** — сколько готовы заплатить за целевое действие. Не знают — гипотеза от LTV/маржи.
- **LTV** — средний доход с клиента за весь срок.
- **Маржа** — % от цены.
- **AVG ticket** — средний чек.

Если нет ни одного — алярма: «Без unit-экономики мы выберем канал наугад. Дайте хотя бы оценку.»

### Поле 6 — Бюджет
- **Общий месячный бюджет** — главное число. Сумма на весь прогон = месячный × горизонт из Поля 11, не «на 3 месяца по методичке».
- **Есть ли разделение по фазам:** тест/опт/масштаб?
- **Есть ли отдельный бюджет на креатив** (продакшн видео, тексты, дизайн)?

**Опорные пороги:**
- <50к/мес — 1 канал, обычно performance
- 50-150к/мес — 2 канала с тестом
- 150-500к/мес — Топ-3 с фазированием
- 500к+/мес — Топ-3 + дополнительные

Бюджет <30-50к/мес — предупреди: «при таком бюджете рекламы маловато данных, рекомендую начать с органики/контента».

### Поле 7 — УТП продукта (финализируется на Шаге 8)
Главное обещание: чем мы отличаемся от 3-5 главных конкурентов.

Если ответ — «качество», «индивидуальный подход», «опытные специалисты» — пометить «нет настоящего УТП, разбираем на Шаге 8».

### Поле 8 — Гео и языки
Какие города/страны приоритетны и какие языки.

### Поле 9 — Сезонность и срочность спроса
- **Срочный** (нужно прямо сейчас — эвакуатор, экстренный ремонт)
- **Отложенный** (исследуют, выбирают — мебель, B2B SaaS, образование)
- **Создание спроса** (новая категория — новый класс продуктов)

Это поле — главный вход для Шага 3 (стратегический слой) и Шага 9 (выбор каналов).

### Поле 10 — Что НЕ делаем
- Какие платформы исключены (например, Meta из-за гео или политики)
- Какие темы / форматы запрещены
- Какие УТП НЕ используем (по правовым причинам)

### Поле 11 — Горизонт планирования (обязательное)

На какой срок считаем стратегию, бюджет и медиаплан. **Одно число на весь прогон.**

- **По умолчанию: 6 месяцев** — для абонентских / retainer-проектов.
- Типовые варианты: 3 / 6 / 12 месяцев. Другой срок — только если маркетолог назвал его явно.
- Подтверждается на старте прогона (Шаг 0) и переносится сюда. На Шагах 3, 10 и 12 **не выбирать заново**.
- Если срок меняется — сначала обнови это поле, получи «ОК» по брифу, потом пересчитай зависимые артефакты.

В `01_brief.md` всегда пиши отдельной строкой в таком виде (по ней читают следующие шаги и скрипты):

`Горизонт планирования: 6 месяцев`

## Защита от типовых ошибок

**Ошибка 1:** «Маркетолог не знает unit-экономику».
- Решение: «Дайте гипотезу. Сколько ОДНА продажа приносит чистыми? От этого max CPA = 1/3-1/4 этой суммы».

**Ошибка 2:** «Бюджет ‘посмотрим как пойдёт’».
- Решение: «Без понимания минимума мы не выберем каналы. Минимум 30к/мес чтобы запустить хоть что-то. Согласны?»

**Ошибка 3:** «Хотим всё гео».
- Решение: «Тест в 1-2 регионах + расширение. Иначе размажемся по 90 регионам с 50к в каждом — без шансов».

**Ошибка 4:** Сайта нет, лендинга нет.
- Решение: предупреди — «без посадочной запуск performance невозможен. Сделайте хотя бы 1-страничный лендинг, иначе только инфлюенс-посевы и контент».

**Ошибка 5:** «Бюджет посчитаем на 3 месяца, стратегию — на 6».
- Проблема: медиаплан, стратегия и бюджет начинают спорить друг с другом.
- Решение: горизонт только из этого поля. Дефолт 6 месяцев. Другой срок — явная правка брифа, не локальный выбор на Шаге 10.

## Гейт

«Всё верно? Я свёл бриф из ваших ответов + парсинга сайта. Горизонт планирования — <N> месяцев. Идём в стратегический слой?»
