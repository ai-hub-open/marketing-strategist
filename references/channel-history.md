# История каналов — что это, где взять, как стратег её использует

**Когда читать:** Шаг 1 (материалы клиента), Шаг 2 (поле 12 брифа), Шаг 9 целиком — раздел
«Как стратег использует историю», Шаг 12 (передача в площадочные скиллы).

**История каналов** — короткая сводка о том, что прошлая реклама клиента реально дала: сколько
потрачено, сколько пришло лидов и по какой цене — по каждому каналу (Директ, VK Ads, Telegram
Ads, посевы…) и внутри Директа по типам кампаний (Поиск, РСЯ, ЕПК, ретаргет).

Зачем стратегу: без неё каналы выбираются «из общих знаний», и стратег уверенно рекомендует
то, что у этого клиента уже провалилось. Классическая ошибка: VK Ads и похожие аудитории в топ-3
клиенту, у которого VK не дал ни одного лида.

Готового отчёта «история каналов» нет ни в Директе, ни в Метрике. Это файл, который собирается
из трёх источников: Директ (расход, клики, конверсии по кампаниям), Метрика (визиты и
конверсии по источникам трафика — видит и не-Директ каналы, если ссылки размечены UTM;
расходов не-Директ каналов в Метрике нет) и слова клиента.

## Контракт файла

> ⚠️ **Этот раздел — общий для трёх скиллов:** `yandex-direct-audit` (производитель файла),
> `marketing-strategist` (этот) и `yandex-direct-manager`. Скиллы ставятся отдельными пакетами
> и не читают файлы друг друга, поэтому контракт продублирован. Меняешь поля — меняй во всех трёх.

Файл — `channel_history.md` (для человека) и/или `channel_history.json` (для скилла), поля
одинаковые.

**Шапка — условия, на которых построены выводы.** Без шапки строкам верить нельзя:

| Поле | Что внутри | Пример |
|---|---|---|
| `site` | сайт / продукт | `example.ru` |
| `period` | период, **выбранный пользователем** | `2026-04-01..2026-09-30` |
| `lead_definition` | что считали лидом: id и названия целей + как выбраны | `[123, 456] «Заявка», «Звонок» — ключевые цели стратегий кампаний` |
| `thresholds` | пороги выводов, **с которыми** построена таблица | `min_clicks: 30, min_days: 14, target_cpa: 3000, expensive_ratio: 1.5` |
| `created_by` | кто и когда собрал | `yandex-direct-audit 2026-10-06` / `со слов клиента` |

**Строки — по одной на канал или тип кампании:**

| Поле | Что внутри | Пример |
|---|---|---|
| `channel` | канал | `yandex_direct`, `vk_ads`, `telegram_ads`, `other` |
| `campaign_type` | тип внутри канала (для Директа обязателен) | `search`, `rsya`, `unified`, `retargeting`, `—` |
| `account` | кабинет / аккаунт | логин кабинета Директа |
| `status` | `ran` — крутилась, `never_ran` — черновик / не запускали, `archived` — в архиве | `ran` |
| `spend` | расход за период, ₽ (без НДС — как в отчётах Директа) | `240000` |
| `clicks` | клики | `3100` |
| `leads` | лиды по `lead_definition` | `96` |
| `cpa` | `spend / leads`; при `leads = 0` — `null` | `2500` |
| `counter_id`, `link` | счётчик и состояние связки Директ↔Метрика (`green` / `yellow` / `red`, см. Шаг 0.5.2) | `12345678`, `green` |
| `source` | откуда цифры | `direct` / `metrika` / `client` |
| `verdict` | вывод (ниже) | `no_leads` |
| `verdict_reason` | **одна строка с числами и порогом**, по которым сделан вывод | `0 лидов при 410 кликах и 62 днях показов (порог «мало данных»: <30 кликов или <14 дней)` |
| `note` | всё остальное, в т.ч. причина, почему не запускали | `не прошла модерацию — медицинская тематика без лицензии` |

**Выводы (`verdict`)** — считаются по порогам из шапки:

| Вывод | Условие по умолчанию |
|---|---|
| `no_data` — мало данных | `clicks < 30` **или** показов меньше 14 дней |
| `no_leads` — не дал лидов | данных достаточно, `leads = 0` |
| `expensive` — дорого | `cpa > target_cpa × 1.5`. Нет `target_cpa` — вывод не ставится, только CPA |
| `works` — работает | данных достаточно, лиды есть, не дорого |
| `never_ran` — не запускали | `status = never_ran`; вывода о канале нет, есть причина в `note` |

**Пороги — не догма.** У бизнеса бывают свои представления о «мало данных» и «дорого» (длинный
цикл сделки, дорогой чек). Поэтому пороги всегда пишутся в шапку, а каждый вывод — с
`verdict_reason`: человек видит, на каких числах построен вывод, и может их поправить.

Пример `channel_history.json`:

```json
{
  "site": "example.ru",
  "period": "2026-04-01..2026-09-30",
  "lead_definition": {"goal_ids": [123, 456], "names": ["Заявка", "Звонок"],
                      "how": "ключевые цели стратегий кампаний"},
  "thresholds": {"min_clicks": 30, "min_days": 14, "target_cpa": 3000, "expensive_ratio": 1.5},
  "created_by": "yandex-direct-audit 2026-10-06",
  "rows": [
    {"channel": "yandex_direct", "campaign_type": "search", "account": "login-1", "status": "ran",
     "spend": 240000, "clicks": 3100, "leads": 96, "cpa": 2500, "counter_id": 12345678,
     "link": "green", "source": "direct", "verdict": "works",
     "verdict_reason": "CPA 2500 ≤ 3000 × 1.5 при 96 лидах", "note": ""},
    {"channel": "yandex_direct", "campaign_type": "rsya", "account": "login-1", "status": "ran",
     "spend": 80000, "clicks": 410, "leads": 0, "cpa": null, "counter_id": 12345678,
     "link": "green", "source": "direct", "verdict": "no_leads",
     "verdict_reason": "0 лидов при 410 кликах и 62 днях показов", "note": ""},
    {"channel": "vk_ads", "campaign_type": "—", "account": "", "status": "ran",
     "spend": 50000, "clicks": null, "leads": 0, "cpa": null, "counter_id": null,
     "link": null, "source": "client", "verdict": "no_leads",
     "verdict_reason": "со слов клиента: 50 тыс. за 2 месяца, ни одной заявки", "note": ""}
  ]
}
```

## Как получить файл (для маркетолога)

| Что нужно | Чем | Что сказать скиллу |
|---|---|---|
| История **Директа** по кабинету | скилл **`yandex-direct-audit`** | «Сделай аудит кабинета `<логин>` и выгрузи историю каналов за `<период>`» → `channel_history.md` / `.json` |
| **Другие каналы** (VK, Telegram, посевы) — визиты и конверсии | скилл **`yandex-metrika-manager`** (отчёт по источникам трафика) | «Покажи каналы трафика и конверсии по источникам за `<период>`» — расходов там не будет, их добавляет клиент |
| Всё, чего нет в данных | клиент словами | канал, период, сколько потратили, сколько было заявок |

⚠️ **Claude Desktop:** файлы одного чата в другом чате не видны. Если аудит делали в другом
чате — файл нужно скачать оттуда и приложить сюда. Либо запускать скиллы в одном чате.

## Как стратег собирает историю (Шаги 1–2)

1. **Файл приложен** (в материалах клиента или к брифу) → проверь шапку: `period`,
   `lead_definition`, `thresholds`. Чего-то нет — спроси именно это. Сохрани как
   `channel_history.md` + `channel_history.json` в `marketing-campaigns/<slug>/` — тем же
   форматом: файл уйдёт дальше в площадочные скиллы без переделки.
2. **Файла нет, но в материалах клиента есть прошлые цифры** («слили 40к в VK, ноль заявок») →
   собери строки сам, `source: client`.
3. **Ничего нет** → поле 12 брифа: спроси одним вопросом (шаблон ниже). Перед сбором со слов
   **всегда спроси период** (по умолчанию его не выбираем) и **что считать лидом** — с вариантами:
   1) ключевые цели кампаний / заявки из CRM — **по умолчанию**; 2) все конверсии, которые
   клиент считал; 3) конкретное событие, которое назовёт клиент.
4. **«Рекламы не было»** → `_state.json` → `channel_history: none`; дальше все рекомендации
   каналов помечаются **«без истории»**.

**Шаблон вопроса (поле 12 брифа):**

```
Чтобы не советовать то, что у вас уже не сработало, мне нужна история рекламы — по каждому
каналу за выбранный вами период: сколько потратили, сколько было заявок, по какой цене.

• Директ — скилл yandex-direct-audit: «Сделай аудит кабинета <логин> и выгрузи историю
  каналов за <период>». Он отдаст channel_history.md — приложите его сюда.
• Другие каналы (VK, Telegram, посевы) — скилл yandex-metrika-manager покажет визиты и
  заявки по источникам; расходы допишите сами.
• Или просто напишите словами: канал → период → потратили → заявок.

Если рекламы раньше не было — так и скажите, пойдём без истории.
```

`_state.json` → `channel_history: file | client | none`.

## Как стратег использует историю (Шаг 9)

История — **вход матрицы каналов, а не примечание к ней.** До подсчёта баллов у каждого канала
матрицы появляется колонка «История»:

| Вывод в истории | Что делает стратег |
|---|---|
| `works` — работает | +1 к критерию «Доказательная база» (это сильнее любого отраслевого кейса); CPA из истории — ориентир для Шагов 10–11 |
| `expensive` — дорого | Канал **не идёт в топ-3 молча.** Если по баллам проходит — гейт с цифрами: «VK Ads: CPA 4 800 ₽ при целевом 2 000 (порог «дорого» ×1,5). Всё равно берём? Что меняем — оффер, аудитории, формат?» |
| `no_leads` — не дал лидов | То же, жёстче: в топ-3 — только явным решением маркетолога **и** с ответом «что меняем по сравнению с прошлым разом». Без ответа — в «Что отбросили» с причиной из `verdict_reason` |
| `no_data` — мало данных | Вывода нет: «данных мало — канал не проверен». Баллы — как без истории |
| `never_ran` — не запускали | Вывода нет; учитывай причину из `note` (отказ модерации → проверь тематику и документы, поле 13 брифа) |
| строки нет | В матрице и в обосновании — пометка **«без истории»** |

**Нет истории вовсе** (`channel_history: none`) — в гейте Шага 9 отдельной строкой: «Каналы
выбраны без истории клиента — по персонам, спросу и отраслевым данным». В `channel_selection.json`
у каждого канала `history: "none"`.

**Пороги выводов** (`thresholds` в шапке) у бизнеса бывают свои — поэтому каждый вывод
показываем с числами и порогом, на которых он построен, а не голым ярлыком.

## Передача дальше (Шаг 12)

`channel_history.md` / `.json` — **обязательный файл передачи** в `yandex-direct-manager` (и в
`vk-ads-manager`, если канал выбран): площадочный скилл не будет спрашивать историю заново и
не повторит провалившийся тип кампаний. Подробно — `references/handoff-to-platforms.md`.
