# Handoff to Platforms — передача в площадочные скиллы

Используется на Шаге 12, после генерации финального отчёта. Задача — **чисто передать готовые артефакты** в специализированные скиллы запуска (yandex-direct-manager, vk-ads-manager, и т.п.), чтобы они не переделывали бриф/гипотезы/УТП с нуля.

## Главный принцип

**Площадочный скилл — оператор, не стратег.** Он не пересматривает выбор канала, не переделывает гипотезы, не сочиняет УТП. Он берёт готовое и делает свою специфическую часть (семантика и объявления для Я.Директа, аудитории и креативы для VK Ads, и т.п.).

## Карта передачи

| Площадка | Скилл | Что передаём |
|----------|-------|--------------|
| Яндекс.Директ (Поиск + РСЯ) | `yandex-direct-manager` | `12_brief_for_yandex_direct.md` (бриф в формате менеджера), `channel_history.md`, `01_brief.md`, `02_strategy.md`, `industry_research.json`, `hypotheses.md` (selected), `07_personas.md`, `usp_final.json`, `kpi_framework.json` (по каналу), доля бюджета из `budget_allocation.json` |
| VK Ads / myTarget | `vk-ads-manager` | то же + персоны с уточнениями «где живёт в VK» (сообщества, интересы) |
| Meta (FB/IG) | пока ручной запуск или Meta-скилл если есть | весь набор + ограничение по гео |
| TikTok / Reels | пока вручную | usp_final + персоны + бюджет на видеопродакшн |
| Telegram Ads | пока вручную | usp_final + персоны + список целевых каналов / тематик |
| Дзен / Promo | пока вручную | usp_final + персоны + контент-план идея |

## Что делает marketing-strategist при handoff

### Шаг 1 — Создаёт `12_handoff_plan.md`

```markdown
# Handoff Plan: <slug>

## Передача в Яндекс.Директ
**Скилл:** yandex-direct-manager
**Месячный бюджет на канал (по фазам):**
- Тест: 75 000 ₽
- Опт: 110 000 ₽
- Масштаб: 130 000 ₽

**Целевые KPI:**
- CPL: Тест ≤900 ₽, Опт ≤700 ₽, Масштаб ≤600 ₽

**Какие гипотезы тестируем:** 1, 4 (из selected)

**Передаваемые артефакты:**
- `12_brief_for_yandex_direct.md` — бриф в формате менеджера (см. ниже)
- `channel_history.md` / `.json` — история каналов (или пометка «без истории»)
- `01_brief.md`
- `02_strategy.md`
- `industry_research.json`
- `hypotheses.md` (с фокусом на Гип. 1, 4)
- `07_personas.md` (фокус на П1, П2)
- `usp_final.json`
- `kpi_framework.json` (раздел "yandex_direct_search" и "yandex_direct_rsya")
- `budget_allocation.json` (раздел по каналу)

**Команда запуска:**
«Запусти yandex-direct-manager. Бриф — 12_brief_for_yandex_direct.md, история — channel_history.md (приложи оба). Контекст в marketing-campaigns/<slug>/. Использовать гипотезы 1 и 4, персоны П1 и П2, основное УТП по usp_final.json. Бюджет и KPI — по фазам из budget_allocation.json и kpi_framework.json.»

## Передача в VK Ads
[аналогично]

## Что НЕ передаём (отдельные треки)
- SEO — отдельный план (см. <ссылка>)
- Telegram Ads — вручную, см. usp_final.json + персона П1
```

## Бриф для Яндекс.Директа — `12_brief_for_yandex_direct.md`

`yandex-direct-manager` начинает с собственного брифа из 13 пунктов и **не подставляет сам**
стоп-поля: что рекламируем, посадочная страница, регион, бюджет, цель (что считаем конверсией),
тематика. Всё это стратег уже знает — поэтому, если Директ в топ-3, на Шаге 12 он собирает бриф
**в формате менеджера**. Менеджер получает его вложением (так его бриф и устроен: «есть
материалы — извлеку, спрошу только недостающее») и не задаёт маркетологу те же вопросы второй раз.

| Пункт брифа менеджера | Откуда берёт стратег |
|---|---|
| 1. Продукт, посадочная страница, целевая аудитория | `01_brief.md` §1 + коротко персоны П1–П2 из `07_personas.md` |
| 2. Тип сайта | `01_brief.md` §1 |
| 3. Регион | `01_brief.md` §2 |
| 4. Месячный бюджет | `budget_allocation.json` — бюджет Директа на **Фазу 1 (тест)**, план по фазам строкой |
| 5. Каналы (Поиск / РСЯ, доли) | `channel_selection.json` — какие стороны Директа в топ-3; доли — из `budget_allocation.json` |
| 6. Тип запросов | не решаем за менеджера: «НЧ + СЧ (дефолт менеджера)» |
| 7. УТП и сужающие слова | `usp_final.json` + углы гипотез из `hypotheses.md` (selected) |
| 8. Цель в Метрике | `01_brief.md` §3 «Конверсия на сайте» |
| 9. CPA и ценность конверсии | `kpi_framework.json` (Директ, Фаза 1) + unit-экономика из брифа |
| 10. Материалы и история рекламы | `channel_history.md` — обязательно; ассеты — если были |
| 11. Slug | slug стратегии |
| 12. Тематика | `01_brief.md` §9 |
| 13. Ограничения | `01_brief.md` §7 |

Стоп-поле не нашлось в артефактах — **не придумывай**, пиши «❗ уточнить»: менеджер спросит
сам. Документ короткий (≤ 1 страницы), без пересказа стратегии.

⚠️ **Claude Desktop:** файлы одного чата в другом не видны. Если менеджер запускается в новом
чате, `12_brief_for_yandex_direct.md` и `channel_history.md` нужно приложить к первому сообщению.

## Что делают площадочные скиллы

**yandex-direct-manager** не пересматривает выбор канала, гипотезы и УТП. Сам делает: разведку
аккаунта (кабинет, счётчик Метрики и его связку с кабинетом, историю каналов — из приложенного
`channel_history.md`, второй раз не спрашивает), маски и семантику Вордстата, кластеризацию,
структуру кампаний (типы с историей «не дал лидов» / «дорого» — только через гейт с цифрами),
минус-слова, цели Метрики, объявления, стратегию торгов, финальную проверку и заливку в черновик
после «ОК». Запускает кампании всегда человек.

То есть marketing-strategist закрывает общую подготовку (бриф, стратегия, каналы, бюджет, KPI), а
площадочный скилл — платформенные шаги.

**VK Ads:**
- Принимает тот же набор
- Свой Шаг — настройка аудиторий VK (LAL, интересы, сообщества), креативы под VK-форматы, парсеры сообществ

**Meta:**
- Аналогично. Свой Шаг — пиксель, аудитории FB/IG, дин-креативы.

## Защита от типовых ошибок

**Ошибка 1:** «Площадочный скилл переделывает гипотезы».
- Решение: явно в SKILL.md площадочного — «если есть `marketing-campaigns/<slug>/hypotheses.md` — используй её, не переделывай».

**Ошибка 2:** «Маркетолог запускает оба скилла одновременно — конфликт».
- Решение: лучше последовательно. Сначала Я.Директ запускается полностью (включая объявления), потом VK.

**Ошибка 3:** «Нет связи между скиллами через файлы».
- Решение: общая рабочая папка `marketing-campaigns/<slug>/`. Артефакты — общие.

**Ошибка 4:** «Площадочный скилл не знает про бюджет на свою фазу».
- Решение: `budget_allocation.json` — обязательный вход. Площадочный скилл читает «свою» долю.

## Артефакт

`12_handoff_plan.md` — финальный документ с маппингом «канал → скилл → файлы → команда запуска».
