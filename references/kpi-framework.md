# KPI Framework — метрики и мониторинг

Используется на Шаге 11. Задача — для каждого выбранного канала задать **что мерим, какие пороги для решений, как часто смотрим**. Чтобы медиабайер не угадывал «когда отключать», а имел триггеры.

## Главный принцип

**KPI — не «следить за всем», а «триггеры действий».** Если для метрики нет действия — она не KPI, а интерес. Каждая метрика должна быть привязана к решению: «если X выше Y — делаем Z».

## Иерархия метрик

```
Бизнес-KPI (главное)              ──→ Цель кампании в брифе
       │
       ├─ Канал-KPI (по площадкам) ──→ CPL/CPA/ROAS по каналам
       │       │
       │       └─ Промежуточные   ──→ CTR, CPC, CR
       │
       └─ Brand-метрики (если применимо) ──→ Поисковые запросы по бренду, share of voice
```

## Шаблон KPI на канал

```markdown
### <Канал> — <Я.Поиск / VK Ads / РСЯ-ретаргет>

**Главная метрика канала:** CPL / CPA / ROAS
**Целевое значение:**
- Фаза 1 (Тест): <значение> (допуск +30% от target)
- Фаза 2 (Оптимизация): <значение> (допуск +10%)
- Фаза 3 (Масштаб): <значение> (target)

**Промежуточные метрики:**
| Метрика | Целевое значение | Когда тревога |
|---------|------------------|---------------|
| CTR | >X% | <X/2% — провал релевантности |
| CPC | <Y ₽ | >Y×1.5 ₽ — аукцион перегрет |
| CR (клик→лид) | >Z% | <Z/2% — посадочная или таргет |
| Bounce | <40% | >60% — нерелевантный трафик |
| Конверсии в день | >N | <N/2 — не выйдем на выборку |

**Триггеры действий:**
- CPL > target × 3 в течение 3 дней → **отключить канал**, разобрать на ретро
- CPL > target × 1.5 в течение 7 дней → **остановить плохие связки**, оставить топ-2
- CPL = target ± 20% и стабильно → **перейти в Фазу 2** (если в Фазе 1)
- CPL < target × 0.7 в течение 7 дней → **увеличить бюджет** на канал на +30%
- CR падает на 30% от базы → **проверить посадочную**, может технический сбой

**Частота отчётности:**
- Daily check (первые 7 дней теста)
- Weekly (после стабилизации)
- Biweekly (масштаб)

**Где смотрим:**
- <Кабинет 1: ссылка/название>
- <Аналитика: Я.Метрика, цели X, Y, Z>
- <Tracking: коллтрекинг, CRM-импорт лидов>
```

## Минимальный набор метрик по типам каналов

### Performance Search (Я.Директ Поиск)
- Главное: **CPL / CPA**
- Промежуточные: CTR (target ≥7-10% по бренду, ≥3-5% по категории), позиция показа, доля показов (impression share), CR
- Brand-метрики: рост запросов по бренду

### Performance Social (VK Ads, Meta)
- Главное: **CPL / CPA / ROAS**
- Промежуточные: CTR (1-2% норма), CPM, частота показа (≤3-4 ок), CR
- Качество лидов: CRM-импорт + scoring + retention 1/7/30 дней

### Display & Retarget (РСЯ-ретаргет, Programmatic)
- Главное: **post-click CR + assist** (атрибуция: ретаргет редко закрывает напрямую)
- Промежуточные: viewability, частота показа, охват
- Бизнес: incremental lift (часть конверсий, которых не было бы без ретаргета)

### Видео и охват (TikTok, Reels, YouTube)
- Главное: **CPM + Engaged View Rate** на тесте, **Brand Lift / Web visits** позже
- Промежуточные: % просмотра до конца, click-to-view ratio
- Качество: incremental brand search lift (поисковые запросы по бренду)

### Контент (Дзен, статьи)
- Главное: **CPV (cost per visit)** или **Read-rate**
- Промежуточные: время на статье, % дочитываний, CR в подписку/триал
- Долгий хвост: assisted-конверсии через 30/60 дней

### SEO (отдельный трек)
- Главное: **органический трафик в семантике** + позиции по ядру
- Промежуточные: рост страниц в индексе, обратные ссылки, технические метрики (Core Web Vitals)
- Скорость: первые движения через 3 месяца, выход на план — 6-12 месяцев

### Инфлюенсеры
- Главное: **CPM на охвате** + **direct conversions через промо-код / UTM**
- Промежуточные: ER (engagement rate) поста, динамика комментариев
- Качество: возвратность аудитории на сайт

## Условия перераспределения бюджета между каналами

- Если канал-1 даёт CPL ≤ target и канал-2 даёт CPL > target × 1.5 → переток +20% бюджета канал-2 → канал-1.
- Если в течение 14 дней лидер не определён → ждём 7 дней, потом сужаем до 1-2 каналов.

- [ ] Top-5 / Worst-5 связок

- [ ] Где добавили
- [ ] Прогноз CPL на следующую неделю

## Защита от типовых ошибок

**Ошибка 1:** «Возьмём все метрики Яндекс.Метрики».
- Проблема: 50 метрик = ни одна не KPI, медиабайер тонет.
- Решение: одна главная + 3-5 промежуточных + 3-5 триггеров.

**Ошибка 2:** «Целевой CPL = тот, что был в брифе».
- Проблема: На тесте этот CPL недостижим, мы преждевременно режем нормальные каналы.
- Решение: 3 значения по фазам с допуском (Тест +30%, Опт +10%, Масштаб target).

**Ошибка 3:** «Будем смотреть еженедельно».
- Проблема: На тесте за неделю проходит половина бюджета, поздно реагировать.
- Решение: Daily первые 7 дней теста — обязательно.

**Ошибка 4:** «Не настроили цели — запустим, потом донастроим».
- Проблема: без целей мы не знаем CPL, всё бесполезно.
- Решение: до запуска — обязательная установка Метрики/Pixel/events.

## Гейт

Покажи маркетологу:
1. Главный бизнес-KPI с targets
2. Сводную таблицу по 3 каналам
3. Чек-листы daily/weekly

В «глубоком» режиме ждёт «ОК». В «поверхностном» — двигаемся сразу к Шагу 12.
